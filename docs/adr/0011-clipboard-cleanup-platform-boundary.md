# 剪贴板自动清除暂不作为 v0.5 安全保证

## 背景

密码复制到系统剪贴板后,应用可以尝试在一段时间后清除当前 primary clip,但 Android 版本、应用后台生命周期、各厂商自研剪贴板、第三方输入法剪贴板历史和系统剪贴板同步行为并不提供统一的跨设备保证。应用进程被挂起或终止时,应用侧计时器也无法保证按时执行;清除当前 primary clip 也不代表已经被其他进程读取的副本或剪贴板历史消失。

## 决策

v0.5 保留密码及秘密字段的复制路径和一次性复制反馈,但移除“20 秒后可靠清除剪贴板”的规划承诺和验收要求,不新增依赖该承诺的用户可见政策。应用不将固定时限自动清除作为安全边界,也不以清除完成消息向用户作出保证。

自动清除若要重新进入规划,必须先完成原生平台方案、后台执行策略、替换内容保护和 Android/iOS 真机兼容矩阵评估,并单独定义可验证的语义。

会话锁定与应用切后台属于应用自身可控的内存边界:应用必须同步丢弃复制控制器持有的明文、计时器与反馈状态,并可在读取到 current primary clip 仍为本应用最近写入值时异步尝试清除。平台 API 不提供原子 compare-and-clear,读取与清除之间仍可能发生外部替换;该限制不改变上述平台能力边界。

## 影响

- 当前 v0.5 的剪贴板安全说明以平台边界和“不记录敏感明文”为准,不声称固定时间清除。
- 普通复制仍需提供清晰的一次性反馈;Android 13+ 还需遵循系统复制确认 UI 的去重规则。
- 锁定后的应用内复制状态可作为确定性验收项;系统、厂商或输入法维护的剪贴板副本仍不作为清除验收项。
- 本决策不回溯修改已关闭的历史 Issue;现有运行时代码是否保留为尽力而为实现,另行通过实现 PR 决定。
