# 数据卫生规范 · PROJECT_SW

> 安全约束见 [SECURITY.md §7](../SECURITY.md)。

## 1. 内存与日志卫生

- 明文密码、KEK、Master Vault Key、DEK 仅在受控作用域内短生命周期持有。
- 尽可能对敏感缓冲区请求 OS 禁止换出(`mlock` 等效;Flutter 侧通过 libsodium 的安全内存 API 与及时清零),使用后立即清零。
- 应用切后台、锁定、超时自动清零内存中的明文与密钥。
- 日志/埋点严禁输出明文敏感字段;对密码、密钥、条目内容一律脱敏(只可记录条目 id、操作类型、耗时、错误码等非敏感元数据)。
- 剪贴板复制敏感字段须遵守平台能力边界并提示用户;应用不把固定时限自动清除作为当前版本的安全保证(详见 §2)。

## 2. 剪贴板卫生(平台方案暂缓)

当前 v0.5:保留敏感字段的普通复制路径和一次性复制提示,不承诺应用在固定时限后可靠清除系统剪贴板。平台原生能力、应用后台生命周期、厂商剪贴板历史及已被其他进程读取的副本之间不存在统一的跨 Android 版本保证;应用侧定时器只能作为尽力而为的实现,不能作为安全边界。

- **覆盖范围**:`password` 与 `custom_fields(secret=true)`(见 [VaultEntry 规格](vault_entry.md))复用同一复制路径;复制非敏感字段(如 username)不触发敏感复制提示。
- **复制提示**:复制密码或秘密字段时只显示一次"密码已复制到剪贴板"提示;不展示倒计时或清除完成消息。
- **平台边界**:Android 28+存在清除当前 primary clip 的原生 API,但不等于清除键盘/厂商剪贴板历史;应用失去焦点、进程挂起或被杀时也不能保证应用定时器执行。Android 13+的系统剪贴板生命周期由系统决定,应用不依赖其实现 20 秒策略。
- **未来专项**:若重新引入自动清除,必须先确定原生 Android/iOS 的清除语义、后台执行策略、替换内容保护和真机兼容矩阵,并单独建立可验收的安全边界。
