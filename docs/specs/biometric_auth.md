# 生物解锁与认证强度 · PROJECT_SW

> 密码学细节见 [SECURITY.md §4/§6](../SECURITY.md)。

## 1. 生物解锁机制

核心原则:生物特征不直接解密任何东西;它只是授权操作系统释放一个硬件保护的密钥。

流程:
1. **首次设置**:用户输入主密码 → 派生 KEK → 解出 Master Vault Key → 用一个硬件密钥库生成的、生物识别门控的密钥 `K_bio` 包裹 Master Vault Key,得到 `biometric_wrapped_master_vault_key`,存入 vault header(同时 `K_bio` 受系统 Keychain/Keystore 管理,`setUserAuthenticationRequired` / `biometryCurrentSet`)。
2. **生物解锁**:用户通过指纹/面容 → OS(硬件)释放 `K_bio` → 解开 `biometric_wrapped_master_vault_key` → 得到 Master Vault Key → 解 DEK → 访问条目。全程不涉及主密码、不执行 Argon2id。
3. **主密码路径始终保留**:主密码 → KEK → 解 `wrapped_master_vault_key`,作为生物失效(换指纹/重置)时的兜底。
4. **生物变更检测**:`K_bio` 绑定当前生物特征集(`biometryCurrentSet` / 等效机制),系统生物特征变更后 `K_bio` 失效,自动回退到主密码路径并提示重新设置生物解锁。

> 注意:生物解锁路径等价于"知道主密码"的便捷替代,其安全强度取决于设备生物识别与硬件密钥库的可靠性,而非密码学本身。文档与 UI 须如实告知用户。

## 2. 认证强度策略(已定)

生物解锁为便捷默认,主密码路径为强度退路与高敏强制项:

### 便捷档(默认)

生物识别通过即可解锁,跳过 Argon2id(§1 流程 2);超时锁定(空闲/切后台)触发后,重新解锁仍允许生物(保留日常便捷性)。

### 强制主密码档

以下场景须走主密码路径(KEK → 解 MVK),生物不可替代:
- ① 应用冷启动 / 进程重启后首次解锁(防进程被重启后仅凭生物重开)
- ② 高敏操作(见下)
- ③ 生物失效(换指纹/重置/变更检测触发)

### 高敏操作枚举(生物不可替代,须当时主密码)

- 修改/删除生物解锁设置本身(防他人用已注册生物偷开后门)
- **修改主密码**:分两路径:① 常规改密码须当时主密码(本条规则);② 忘码恢复为隐式应急通道,生物协助,带门槛与冷却(见 [lock_and_recovery.md](lock_and_recovery.md))
- **导出/擦除密码库**:分两路径:① 正常擦除(解锁态)须当时主密码(本条规则);② 死锁擦除(锁定态逃生)为隐式应急通道,不要求主密码,带摩擦(见 [lock_and_recovery.md](lock_and_recovery.md))
- 发起/接收局域网迁移(跨设备数据流动,防生物冒用后把条目迁到他人设备)

### 用户可配置开关

用户可选择全局禁用生物解锁,始终走主密码。

### 风险立场(显式)

项目接受生物特征可被冒用的残余风险(强度归 OS/硬件),以「主密码兜底 + 高敏强制 + 用户可禁用」为退路,不承诺生物路径的绝对强度。

### UI 告知

设置生物解锁与每次强制主密码时,均须如实告知强度边界与触发原因。
